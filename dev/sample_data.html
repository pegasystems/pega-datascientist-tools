Shared synthetic sample data¶

pdstools.demo_data() returns the datamart, prediction and Interaction History views of one seeded synthetic world, generated on demand without customer data:

from pdstools import demo_data

demo = demo_data()
demo.datamart.plot.bubble_chart()
demo.prediction.plot.performance_trend()
demo.ih.plot.success_rate()

Views are built on first access and cached per process for the same arguments, so treat them as read-only. pdstools.ADMDatamart.from_mock_data(), pdstools.Prediction.from_mock_data(), pdstools.IH.from_mock_data() and pdstools.ImpactAnalyzer.from_mock_data() return a single view of the same world.

demo.write_ds_export(path) writes the model, predictor and prediction views as Pega dataset export zips, for example to try the command line or the Streamlit upload flows with real files. The reproducibility foundations, catalogs and world object are internal.

To include the matching prediction view in a report generated from the bundle, pass it explicitly:

demo.datamart.generate.health_check(prediction=demo.prediction)

Rendering the Health Check template without input paths uses all three demo views. Reports generated from supplied model data do not substitute synthetic predictions when prediction data is absent.

Source selection¶

demo_data(source="generated") is the default and is used by reports and notebooks. It generates a reproducible world on demand, using the requested window and seed.

The applications can use the fixed versioned snapshot instead:

demo = demo_data(source="snapshot")
demo.datamart
demo.prediction
demo.ih

Snapshot mode loads the Pega dataset-export zips under data/ in a source checkout, or downloads those same files from the repository’s master/data raw-file URL when installed without the source tree. It is fixed at 182 days, seed 42, scale 1, 100000 interactions, ending November 15, 2026; generation options cannot be changed in snapshot mode. The filenames preserve the standard Pega dataset name and timestamp, followed by _GeneratedDemoData.zip.

DemoData.write_ds_export(path, suffix="GeneratedDemoData") regenerates the four versioned zips (ADM model snapshots, predictor binning, Prediction Studio snapshots, and Interaction History) in Pega’s zip format. Impact Analyzer data is derived from the matching Interaction History rather than stored separately.

The historical cdh_sample() function remains available at both pdstools.cdh_sample and pdstools.datasets.cdh_sample for compatibility. It loads the original ADM archives and is not used by current reports, notebooks, or apps.

Maintained specification¶

The package-owned specification contains the fictional action hierarchy, treatment baselines, channel volumes, model configurations, predictor policies, distributions and timed stories. Frozen records and tuples make the specification immutable and hashable. Construction validates references, probability and volume constraints, exclusive Web Loans routing and its deny-by-default predictor policy.

Catalog model contexts distinguish primary, challenger and derived Omni views. AGB configuration-summary rows will be generated separately and are not extra action-level contexts. The internal specification derives a fresh catalog manifest and Markdown rationale tables from these records; neither is a second maintained copy of the catalog.

These are synthetic metadata tables, not generated model snapshots or private source-document audit records. Predictor distributions describe marginal shapes; they are not instructions to sample correlated fields independently. Action-channel volume weights give Sales and Service the largest response shares in the main channels, with smaller Retention and Risk shares. Actual shares vary with action lifetimes, model histories and sampled decisions.

Calendar contract¶

Notebooks, articles and default reports omit the end date, so their generated data ends on the most recent completed Sunday in UTC. Windows contain exactly the requested number of dates (182 by default), with a minimum of 56; a 60-day window consequently has a partial first week.

An explicit end date is normalized to the Sunday on or before that date. The optional end="canonical" pins the reference window to Sunday, July 2, 2000, for deterministic comparisons and tests; its default 182 dates start on Monday, January 3. Every timestamp shift is a whole number of weeks, preserving weekdays and weekly stories. ADM model/predictor and Prediction views change only their timestamps when the end date shifts.

Interaction History assigns experiment groups and policy decisions by the actual calendar month of each exposure. Changing the end date can therefore also change IH decisions and Impact Analyzer aggregates. With matching arguments, including a fixed seed and window, the Impact Analyzer mock reconciles with the corresponding IH sample. Separate calls with seed=None draw independent worlds.

Shared world¶

One immutable world holds the expected, noise-free behaviour of every channel on every window day: response volume, model-chosen success rate, lift over random selection, model AUC and delayed-feedback state. Every view samples noise around the same world, so Prediction Studio, ADM and Interaction History tell consistent stories: Mobile learning and its AGB challenger, the Email feed dip with negative lift, Web and Email weekend dips, and positive-only weeks followed by a burst of negatives. Story days rescale to shorter windows by whole weeks, keeping weekdays intact.

The prediction view emits the real snapshot shape: a Daily AUC row per prediction at noon with full totals, and Test, Control and NBA rows at midnight. The model-control experiment uses 1 percent of traffic. Same-day arms share part of their outcome noise, as they see the same customers and context, so the small arms still show the lift story. Call Center has no NBA row and its tiny arms are deliberately invalid.

ADM views¶

The model snapshot view has one row per model per day for the 864 action-level models, plus AGB configuration-summary rows that the loader drops after using their importance. Actions launch and retire during the window; Mobile models mature from about 1.2 to 2 percent success rate. A few models are seeded as stuck (no active predictors), weak, or overfitting. Web Risk and Email Service also have weaker, but generally not failed, models so the Health Check shows a few lower-performing contexts alongside the stronger ones.

The predictor binning view describes the last snapshot. Its bin totals reconcile exactly with the model snapshots, and each stored Performance is the AUC of the emitted bins. Naive Bayes predictors have about five bins and a median univariate AUC of about 0.56; numeric bins use one cut grid per predictor, so aggregation can align bins across models. Customer and clickstream signals appear alongside Interaction History and Param predictors, and three shared predictors lead both Mobile configurations. Param.CallToActionStyle is deliberately missing from every observation, so it remains inactive and appears as a 100% missing predictor in the Health Check; Param.CreativeFormat has some missing values. AGB models carry feature importance only; their context keys are inactive at model level but ranked in the configuration summary.

Standard configurations also include Customer.ChurnRiskModelScore, a synthetic, precomputed customer churn-risk score. By default, a naming-pattern match categorizes names ending in ModelScore as External Model in both Naive Bayes and AGB plots; ordinary fields such as Customer.CreditScore keep their Customer category. Custom categorization can override the default. The score is not included in the stricter Web Loans configuration; no external model is downloaded or run.

Interaction History and Impact Analyzer views¶

The Interaction History view samples decisions from the same world: Web and Mobile show one or two offers, Email one, and the Call Center a small share of outbound contacts. Each offered action is an exposure with one impression (Impression inbound, Pending outbound) followed by its responses: Clicked on Web and Mobile, Opened then Accepted on Email, or Accepted on Call Center. Conversion events are also generated for the conversion experiment. Accepts carry the action’s synthetic value. Channel success rates track the world, and Mobile mixes Naive Bayes and AGB decisions after its challenger starts. The Mobile AGB challenger has less noise in its propensity estimates, giving it a modest predictive advantage. AUC is still calculated from sampled outcomes, so weekly results can overlap or reverse; no smoothing or post-hoc performance adjustment is applied.

Every customer belongs to one Impact Analyzer control group per month. The five stock experiments each hold about 1 percent of customers, sharing the NBA group as their test arm, and each arm changes the arbitration: random relevance, propensity only, no business levers, no engagement policies, or a random instead of a model propensity in the model-control arm. The Impact Analyzer view aggregates these exposures per day, control group, channel and action, so it reconciles exactly with the Interaction History. Arms on small channels or short windows can be empty or without accepts; they are never filled in.

Randomness contract¶

Each entity has a local random stream derived from the root seed and its ordered identity components using SHA-256. Adding or reordering unrelated catalog entries does not perturb existing streams. Python’s process-randomized hash() and the global random state are not used.

The generator will use Polars and the Python standard library. Generated sample rows are not bundled assets, and the published legacy sample archives remain unchanged.
